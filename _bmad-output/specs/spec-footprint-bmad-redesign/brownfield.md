# Brownfield 現況分析

## 專案輪廓

- 單頁 React 19 + Vite 7 應用，沒有路由、後端、資料庫或測試框架。
- `App.jsx` 同時承擔設定表單、遊戲狀態、隨機資料產生與結果訊息。
- `GhostLeg.jsx` 以 SVG 繪製梯線、計算路徑、管理動畫與自訂橫線。
- 樣式幾乎全在 `src/index.css`，但畫面仍混用大量 inline style；`src/App.css` 為空檔。

## 可保留的核心

- 遊戲資料完全在瀏覽器產生，符合靜態部署與低維運成本。
- 路徑依橋接線由上而下計算，資料模型簡單且容易驗證。
- SVG 適合表達可縮放的梯線與動畫路徑，不需要換成 Canvas。

## 主要風險

- `GhostLeg.jsx` 將繪圖、幾何、動畫與互動綁在單一元件，後續測試與修改成本高。
- 新指派在前一段動畫完成前仍可能覆蓋 active player，造成結果或視覺競態。
- 自訂橫線的點擊座標假設 SVG 未縮放；在響應式縮放下可能放錯列。
- 固定 600px SVG 與旋轉獎品文字使手機需水平捲動，結果對應不易掃讀。
- 目前主要靠 SVG `text`、`circle` 點擊，鍵盤與輔助科技可操作性不足。
- 沒有自動測試；lint/build 只能證明語法與打包，不能證明路徑正確。

## 設計原則

1. 設定與遊戲分成兩個清楚階段，每個畫面只保留一個主要行動。
2. 目前輪到誰、還剩幾人、最新結果永遠在梯線之外也能讀到。
3. 色彩不作為唯一狀態提示；搭配編號、文字與圖示。
4. 桌面保留完整梯線，手機以可預期的橫向畫布搭配固定提示列。
5. 先封裝純函式與互動狀態，再擴充測試，不在本次引入全域狀態管理。
