# Footprint — Experience Spine

## Foundation

單一響應式 Web 應用，主要在手機與筆電的共用瀏覽器使用。沒有外部 UI 元件庫；以語意化 HTML、CSS 與 SVG 建立介面。`DESIGN.md` 是視覺準則，本文件定義資訊架構與行為。所有資料只存在目前頁面工作階段。

## Information Architecture

| Surface | Reached from | Purpose |
|---|---|---|
| 遊戲設定 | 首次開啟／「開新一局」 | 輸入人數、玩家與任務，產生遊戲 |
| 遊戲進行 | 「開始抽籤」 | 看回合、選起點、追蹤結果、調整橫線 |

不設導覽列、抽屜或巢狀 modal。頁首保留品牌與 Coffee 外連；主要狀態與行動都在當前表面內完成。

## Voice and Tone

| Do | Don't |
|---|---|
| 「輪到 Alice 選一條路」 | 「Current Turn: Alice」 |
| 「4 位玩家，4 個未知任務」 | 「Number of Players」 |
| 「Alice 抽到：唱一首歌」 | 「Alice gets 唱一首歌!」 |
| 「大家都選好了，可以重播任一路徑。」 | 「All players have chosen!」 |
| 指令先說動作，再補原因 | 用 emoji 取代必要文字 |

## Component Patterns

| Component | Use | Behavioral rules |
|---|---|---|
| 品牌標頭 | 全域 | Logo 回到視覺起點但不重設資料；Coffee 在新分頁開啟。 |
| 人數步進器 | 遊戲設定 | 範圍 2–20；可鍵入或用 ±，變更後同步玩家／任務列。 |
| 玩家／任務列 | 遊戲設定 | 每列一組；空姓名在開始前顯示欄位錯誤並聚焦第一個錯誤。 |
| 主要按鈕 | 各表面 | 設定頁為「開始抽籤」；遊戲頁沒有競爭的第二個主要按鈕。 |
| 回合膠囊 | 遊戲進行 | 顯示目前玩家與剩餘人數；動畫進行時鎖定新的未選起點。 |
| 起點按鈕 | 梯線舞台 | 使用真正的 button 覆蓋在 SVG 上；未選／已選／進行中／完成狀態皆有文字標籤。 |
| 橫線命中區 | 梯線舞台 | 點擊空白欄位新增；用 SVG座標轉換而非 DOM 像素假設。 |
| 結果票券 | 遊戲進行 | `aria-live="polite"` 宣告動畫完成結果；永遠顯示玩家名與任務。 |
| 次要工具列 | 遊戲進行 | 「清除自訂線」只在存在自訂線時顯示；「開新一局」始終可用。 |

## State Patterns

| State | Surface | Treatment |
|---|---|---|
| 初始 | 遊戲設定 | 預填 4 位示例玩家與隨機任務，主按鈕可用。 |
| 表單錯誤 | 遊戲設定 | 欄位邊線＋文字訊息；不可只變色。 |
| 等待選路 | 遊戲進行 | 回合膠囊顯示首位玩家；所有未佔用起點可操作。 |
| 動畫中 | 遊戲進行 | 鎖定新的未選起點；保留新遊戲控制但避免誤觸。 |
| 單人完成 | 遊戲進行 | 結果票券更新；已完成路徑可重播。 |
| 全員完成 | 遊戲進行 | 顯示完成訊息；所有已選起點可重播。 |
| 窄螢幕 | 兩者 | 內容單欄；梯線位於明確可橫向捲動的舞台，不壓縮文字。 |
| Reduced motion | 遊戲進行 | 路徑直接完成或縮短至近乎即時，結果仍正常宣告。 |

## Interaction Primitives

- 點擊或 Enter／Space 觸發按鈕；Tab 順序依畫面閱讀順序。
- SVG 的裝飾線條不可成為焦點；起點必須有 HTML button 或等價的完整鍵盤語意。
- 動畫期間禁止指派下一人，避免 active player 與結果競態。
- 已完成起點可重播，但不改變分配或隊列。
- 自訂橫線不得與同列相鄰橫線衝突；清除只影響使用者新增線。

## Accessibility Floor

- 目標 WCAG 2.2 AA；正文與控制文字對比至少 4.5:1。
- 所有互動目標至少 44×44px；`:focus-visible` 使用 `{colors.focus}` 明確外框。
- 狀態不只靠顏色：搭配編號、姓名、「完成」文字或勾號。
- 結果區使用 polite live region；不可在動畫每一幀朗讀座標。
- 支援 200% 文字放大；表單與工具列可換行，不截斷主要行動。
- `prefers-reduced-motion: reduce` 下停用位移與長動畫。

## Responsive & Platform

| Breakpoint | Behavior |
|---|---|
| ≥ 900px | 設定頁雙欄；遊戲頁工具列同行；舞台置中。 |
| 600–899px | 所有內容單欄；玩家／任務仍維持同列。 |
| < 600px | 玩家／任務列內上下排列；梯線舞台以 600px 最小內容寬橫向捲動。 |

這是 responsive web，不假裝原生 App。iOS Safari 與 Android Chrome 都必須完成主要流程；hover 只作增強，不能承載唯一操作。

## Inspiration & Anti-patterns

- **採用桌遊規則卡：** 首頁先說明三個短步驟，降低第一次使用門檻。
- **採用紙筆抽籤：** 一張主要紙面容納核心工作，不用儀表板卡片拼貼。
- **拒絕賭場視覺：** 不使用霓虹、籌碼、拉霸或勝負音效，避免把派對任務包裝成賭博。
- **拒絕 hover-only SVG：** 觸控與鍵盤使用者必須取得完全相同的選路能力。

## Key Flows

### Flow 1 — 主持人小晴在聚會開始一局

1. 小晴用手機開啟 Footprint，看見一句玩法與三步驟提示。
2. 她把人數從 4 改成 6；頁面新增兩列並保留原有四列內容。
3. 她逐列輸入姓名與任務，按「開始抽籤」。
4. 遊戲表面顯示「輪到小晴」及 6 個未選起點。
5. **高潮：** 她把手機放到桌中央，每個人都能立即理解要輪流選一條路。

錯誤：若有空姓名，留在設定頁、聚焦第一個空欄並顯示「請輸入玩家名稱」。

### Flow 2 — 阿哲選路並看懂結果

1. 回合膠囊顯示「輪到阿哲」。
2. 阿哲點第 3 個起點；其他未選起點暫時鎖定。
3. 螢光路徑沿梯線前進，起點按鈕同時顯示他的名字。
4. 路徑抵達終點，結果票券更新並由輔助科技宣告。
5. **高潮：** 阿哲看到「阿哲抽到：學貓叫三聲」，梯線底部也標出對應關係。

Reduced motion：不播放 2 秒位移，立即顯示完整路徑與相同結果。

### Flow 3 — 小晴調整並重播

1. 下一人選路前，小晴在兩條直線間點一下，新增虛線橫橋。
2. 玩家完成後想確認結果，她點已完成起點。
3. 系統重播相同路徑，不改變隊列。
4. 她按「清除自訂線」，只移除自己新增的虛線。
5. **高潮：** 全員結束後，她仍可重播任一路徑，或按「開新一局」回到保留姓名的設定表面。
